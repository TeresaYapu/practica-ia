# Procedimiento para Revisar Cambios

Cada vez que el usuario te pida revisar un cambio de código, debes responder siempre con estos 3 puntos estructurados:

1. 🔍 **¿Qué hace el cambio?:** Explica en 2 frases simples qué agrega o corrige.
2. ⚠️ **¿Qué riesgos tiene?:** Analiza si puede romper algo existente, causar lentitud o fallar con datos inesperados.
3. 🧪 **¿Qué falta probar?:** Menciona 2 casos límite que deberíamos probar antes de dar el visto bueno (ej: números negativos, textos vacíos, división por cero).
